# Проверка новых функций логирования

## ✅ Реализованные функции

### 1. Логирование в файл (+20)
- ✅ Логи **всегда** пишутся в файл (по умолчанию `logs/app.log`)
- ✅ Не требуется настройка, работает из коробки

### 2. Ротация файлов по размеру (+10)
- ✅ Автоматическая ротация при достижении максимального размера
- ✅ Старые файлы сохраняются с timestamp в имени
- ✅ Хранится последние 5 ротированных файлов

### 3. Переменная окружения для размера файла (+10)
- ✅ `LOG_MAX_FILE_SIZE_KB` - максимальный размер в KB (по умолчанию 100)

### 4. Отдельный файл для ошибок (+10)
- ✅ Все ошибки пишутся в `logs/error.log` (по умолчанию)
- ✅ Ошибки также дублируются в основной файл `logs/app.log`
- ✅ Настраивается через `ERROR_LOG_FILE`

### 5. Уровни логирования Nest.js с приоритетами (+20)
- ✅ Используются уровни из `@nestjs/common`: `error`, `warn`, `log`, `debug`, `verbose`
- ✅ Поддержка числовых значений (0-4) и строковых
- ✅ При установке уровня N логируются все уровни от 0 до N включительно
- ✅ Настраивается через `LOG_LEVEL`

## 📋 Как проверить

### 1. Запустите приложение

```bash
npm run start:dev
```

### 2. Проверьте создание файлов логов

После запуска проверьте, что созданы файлы:
```bash
ls -la logs/
# Должны быть:
# - app.log (основной файл)
# - error.log (файл ошибок, если были ошибки)
```

### 3. Проверьте логирование запросов

```bash
curl http://localhost:4000/user -H "Accept: application/json"
```

Проверьте содержимое `logs/app.log`:
```bash
tail -n 5 logs/app.log
```

### 4. Проверьте логирование ошибок

```bash
curl -X GET http://localhost:4000/user/invalid-uuid -H "Accept: application/json"
```

Проверьте оба файла:
```bash
# Основной файл (должна быть ошибка)
tail -n 5 logs/app.log

# Файл ошибок (должна быть та же ошибка)
tail -n 5 logs/error.log
```

### 5. Проверьте уровни логирования

#### Тест уровня 0 (только ERROR):
```bash
# В .env установите:
LOG_LEVEL=0
# или
LOG_LEVEL=error
```

Перезапустите приложение и выполните:
```bash
curl http://localhost:4000/user
```

В логах должны быть **только** ошибки (если они есть), без INFO/LOG сообщений.

#### Тест уровня 2 (ERROR, WARN, LOG):
```bash
# В .env установите:
LOG_LEVEL=2
# или
LOG_LEVEL=log
```

Перезапустите приложение. Теперь должны логироваться ERROR, WARN и LOG уровни.

#### Тест уровня 4 (все уровни):
```bash
# В .env установите:
LOG_LEVEL=4
# или
LOG_LEVEL=verbose
```

Перезапустите приложение. Теперь должны логироваться все уровни.

### 6. Проверьте ротацию файлов

#### Быстрый тест (временно измените размер):

Создайте небольшой скрипт для генерации большого количества логов:

```bash
# В .env временно установите:
LOG_MAX_FILE_SIZE_KB=1  # Очень маленький размер для теста

# Перезапустите приложение
npm run start:dev
```

Затем в другой консоли:
```bash
# Отправьте много запросов
for i in {1..200}; do
  curl -s http://localhost:4000/user > /dev/null
done
```

Проверьте ротацию:
```bash
ls -la logs/
# Должны быть файлы вида:
# app.log
# app-2025-12-13T18-00-00-000Z.log
# app-2025-12-13T18-01-00-000Z.log
# и т.д.
```

**Важно:** После теста верните нормальный размер файла:
```bash
LOG_MAX_FILE_SIZE_KB=100
```

## 📊 Примеры конфигурации

### Минимальная конфигурация (.env)
```bash
PORT=4000
LOG_LEVEL=log
LOG_MAX_FILE_SIZE_KB=100
```

### Полная конфигурация (.env)
```bash
PORT=4000
LOG_LEVEL=2
LOG_FILE=application.log
ERROR_LOG_FILE=errors.log
LOG_DIR=logs
LOG_MAX_FILE_SIZE_KB=500
```

### Примеры уровней логирования

| LOG_LEVEL | Логируемые уровни | Описание |
|-----------|-------------------|----------|
| `0` или `error` | ERROR | Только ошибки |
| `1` или `warn` | ERROR, WARN | Ошибки и предупреждения |
| `2` или `log` | ERROR, WARN, LOG | Ошибки, предупреждения, информация |
| `3` или `debug` | ERROR, WARN, LOG, DEBUG | Все кроме verbose |
| `4` или `verbose` | ERROR, WARN, LOG, DEBUG, VERBOSE | Все уровни |

## 🔍 Структура файлов логов

После работы приложения структура может выглядеть так:

```
logs/
├── app.log                    # Основной файл логов
├── error.log                  # Файл ошибок
├── app-2025-12-13T18-00-00Z.log  # Ротированный основной файл
├── app-2025-12-13T18-01-00Z.log
├── error-2025-12-13T18-00-00Z.log # Ротированный файл ошибок
└── error-2025-12-13T18-01-00Z.log
```
